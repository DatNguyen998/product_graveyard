📜 Changelog

What changed in each version of Big Tech Graveyard, and exactly which files/functions it touched. Full source: CHANGELOG.md.
v0.6.0 Animation engine swapped to Anime.js 2026-08-30
AddedChanged
  • Anime.js v3.2.1 (cdnjs) is now the animation engine for both pages, loaded via a pinned CDN script tag. All animation is progressive enhancement — if the CDN is blocked, both pages still work correctly, just without motion (a small CSS fallback keeps the spinner and "scheduled" pulse going).
    Impacts graveyard.html changelog.html new <script src=cdnjs.../anime.min.js>
  • Added a FLIP-style reorder animation for table rows on sort/filter (captures old position, animates into the new one) instead of the table jumping. New rows still fade/slide in. Skipped above 150 visible rows to avoid jank.
    Impacts graveyard.html render() — rewritten keyOf() — new
  • Added an anime.timeline() to sequence the initial page reveal (card → stats → controls), and a small scale "pop" on company chip click.
    Impacts graveyard.html introAnimation() — new buildChips()
  • Replaced every hand-rolled animation (stat count-up, row entrance, bar growth, scheduled-badge pulse, loading spinner) with an Anime.js equivalent. animateCount() now tweens a plain object via anime() instead of a manual requestAnimationFrame loop.
    Impacts graveyard.html animateCount() — rewritten removed: @keyframes fadeInUp schedPulseAnim — new (paused/replaced each render)
  • This page got the same treatment: card fades in, then each timeline entry staggers in via anime.stagger(), replacing the old CSS @keyframes fadeInUp.
    Impacts changelog.html new inline <script> block
v0.5.0 Static data snapshot instead of live client-side fetch 2026-08-17
AddedChanged
  • graveyard.py now also writes graveyard_all.meta.json (generation timestamp, per-company counts, source credits) alongside its existing JSON/CSV/XLSX output.
    Impacts graveyard.py main() — new metadata block
  • Added a GitHub Actions workflow that runs graveyard.py daily (plus on-demand and on pushes touching graveyard.py) and commits the refreshed snapshot back to the repo — this is what keeps the "database" current without a server.
    Impacts .github/workflows/refresh-data.yml — new
  • graveyard.html no longer calls the three upstream sources itself — it now reads the committed graveyard_all.json snapshot instead, removing the duplicated JS parsing logic entirely.
    Impacts graveyard.html removed: SOURCES/parseKbg()/parseKba()/PARSERS/clean()/yr() added: DATA_URL/META_URL computeStatus() — new loadMeta() — new load() — rewritten buildChips() — rewritten render() — simplified
  • Documented the new snapshot architecture and updated usage instructions.
    Impacts README.md no code impact

Changed

v0.3.0 Brighter UI + motion 2026-08-12
AddedChanged

    Impacts graveyard.html animateCount() — new renderStats() — extracted
